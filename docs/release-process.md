# Release process

<!-- release: 3.0.0 -->

## 1. Prepare

```bash
pnpm install
pnpm check          # compile + lint + test + build + probe smoke test
pnpm changelog --minor   # bumps package.json and writes CHANGELOG.md
```

WXT derives `manifest.version` from `package.json`. Do not edit the built
manifest by hand. The version must be four dot-separated integers or fewer and
strictly greater than the published one.

Update the `<!-- release: X.Y.Z -->` marker in `docs/architecture.md` and this
file, and the feature list in `README.md`, in the same change.

## 2. Build and inspect

```bash
pnpm build
cat .output/chrome-mv3/manifest.json   # permissions, content scripts, version
pnpm zip                               # .output/postmessage-catcher-<version>-chrome.zip
```

The zip must contain `manifest.json` at its root. Load
`.output/chrome-mv3` unpacked and run the manual smoke test in
[`AGENTS.md`](../AGENTS.md#verification).

## 3. Publish

Chrome Web Store submission is manual:

1. Upload the zip in the developer dashboard.
2. Confirm the permission justifications match `docs/privacy.md` and
   `docs/architecture.md`.
3. Review the store listing: screenshots at 1280×800 (or 640×400), 440×280
   promo tile, 1400×560 marquee, 128×128 icon.
4. Submit for review.

Store assets are not generated by a script yet. Until they are, capture the
panel at a realistic width in both themes and keep the source images out of the
shipped bundle.

## 4. Tag

```bash
git tag v3.0.0
git push origin v3.0.0
```

A `v*` tag is intended to trigger `.github/workflows/release.yml` (checks, zip,
GitHub Release with the zip attached). That workflow is not added yet; until it
is, attach `.output/postmessage-catcher-<version>-chrome.zip` to the GitHub
release manually.
